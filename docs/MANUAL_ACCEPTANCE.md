# 开发交付与手动验收

更新：2026-11-21，北京时间。本轮已使用合成音频完成核心真实 RTC 浏览器验收。下列场景可用于补测物理设备与扩展用例。已验证范围见 [验收记录](MANUAL_RESULTS.md)。

## 1. 最短启动方式

在仓库根目录打开 PowerShell。按 [README](../README.md) 安装依赖并启动一次普通模式，生成本地数据库和应用密钥，再运行 `.\stop.cmd`。参考 [`backend/.env.example`](../backend/.env.example) 补齐自己的模型、Embedding 与 RTC 凭据，保留已有数据库和应用密钥。将 [`backend/voice_config.example.json`](../backend/voice_config.example.json) 复制为 `backend/voice_config.json`，填写语音配置。构建语音前端后，按本文配置 ngrok；首次使用向量检索需先同步 Milvus。

```powershell
.\start-voice.cmd -NgrokExe (Get-Command ngrok).Source
```

然后访问 <http://127.0.0.1:5178>，注册或登录自己的账号，点击客服页中的“打开语音渠道”，在新页点击“通话”，允许麦克风并开始讲话。建议使用耳机，减少扬声器声音回流。

依赖和云配置就绪后，脚本会启动本工程独立 PostgreSQL/Milvus、两个前端、融合后端和临时 ngrok；把本次 HTTPS 地址传给后端，验证当前商品知识的 Milvus 记录后启用。无需手工复制每次变化的隧道地址。**脚本不会自动拨打通话、请求模型或重新生成 Embedding。** 点击通话、发问、创作或配图后才会按对应服务产生调用。

如果之前开着本工程模拟版，请先运行 `.\stop.cmd` 再启动语音版。脚本遇到占用端口会明确退出，不会替换其他应用。

Windows PowerShell 5.1 请使用以上 `.cmd` 入口。它在独立 PowerShell 进程中以 `-NoProfile -ExecutionPolicy Bypass` 调用本工程脚本，不改 CurrentUser/LocalMachine 的永久执行策略。四个 PowerShell 脚本已使用 UTF-8 BOM，避免 5.1 把中文按 ANSI 误读；本机 5.1 离线预检已通过。直接运行 `.ps1` 若提示“未数字签名/禁止运行脚本”，使用 `.cmd` 即可，不需要去掉 `\.\` 前缀或永久放开系统策略。若执行策略由组织组策略强制管理，命令行参数不会覆盖它，应遵循相应管理要求。

只检查本地配置、不启动任何服务：

```powershell
.\start-voice.cmd -NgrokExe (Get-Command ngrok).Source -CheckOnly
```

手测结束先点语音页底部挂断图标，再运行：

```powershell
.\stop-voice.cmd -StopInfrastructure
```

关闭脚本会尝试停止本工程数据库里仍活跃或启动结果不确定的 RTC 任务，再关闭本机进程、隧道和本工程容器；保留数据库卷。若提示云任务清理失败，需要重试关闭脚本或到 RTC 控制台核对对应任务，不能将本地窗口关闭等同于云任务已结束。

## 2. 建议按顺序手测

每条记录“通过/失败/未测”和现象即可。不要为了完整记录而反复进行长时间通话。

1. **基本通话。** 进入后听到欢迎语；询问“耳机拆封后能退吗？”应出现用户字幕和有条件的售后回答，并能听到与回答对应的语音。只有欢迎语或只有启动成功提示不算通过。
2. **商品与多轮。** 询问“SC-PB27 这款充电宝多重？”应引用资料中的 568g；再问“那尺寸呢？”应沿用同一商品。若 ASR 把型号识别错，先看字幕确认识别结果，记录它与检索/回答错误的区别。
3. **插话。** 在助手正在回答时说出一个不同的问题，例如“先说一下退货运费谁承担”。应停止旧答复并回答新问题；再试一次“点此打断”按钮。记录能否打断以及是否继续重复旧内容。
4. **挂断重连。** 正常挂断，页面回到可通话状态；再次点击通话，麦克风重新采集、字幕和回答均正常。静音后挂断再连，也应恢复可用输入。
5. **边界。** 问“SC-PB999 多重？”应说明资料不足，不套用 PB27 参数；问“帮我直接退款/查询订单”不能声称操作已完成。
6. **语音确实进入融合工程。** 回到同账号工作台，点击“刷新会话”，选择“语音咨询”。应看见已完成的问题、回答和来源；选择一轮转为内容任务，确认摘要，生成草稿。后续按正常人工审稿、批准和 FAQ 发布流程操作。部分被插话中断的回答可能未完成持久化，应使用已完整回答的一轮。
7. **长流程隔离。** 内容任务生成中或停在人工审核时，语音仍可咨询。配图是独立按钮，不需要为测试文本闭环额外点配图。

手测结果可记录到 [人工验收记录](MANUAL_RESULTS.md)。未实际手测前保留“未测”，不把自动化 Mock 结果填入真实语音栏。

## 3. 常见问题定位

- 页面显示“模拟生成”：运行的是普通模拟版。先停止本工程，再用 `start-voice.cmd`。
- 提示端口占用：默认占用 8010、8011、5178、5179、4041。确认应用归属后处理；脚本不会自动结束未知进程。
- 如果旧版关闭脚本输出已停止但端口仍占用：已修复 Windows PowerShell 5.1 的 PID 数组读取及孤儿子进程识别。使用当前 `stop-voice.cmd` 再关闭，它会在归属核验后清理本工程进程，并实际检查端口；不要改用会被签名策略拦截的 `.ps1`。
- 新窗口被拦截：允许 127.0.0.1:5178 打开新窗口，再点击语音入口。
- 交换码失效：从工作台重新点击入口；交换码一次性且 60 秒过期，语音专用授权约 15 分钟。不要收藏带交换码的 URL。
- 能听欢迎语，但没有用户字幕：先看语音页“麦克风/输入音量/音频上行”指标及设备设置。欢迎语不证明麦克风和 ASR 正常。
- 有用户字幕，但没有回答：先看本工程 `.runtime/backend-error.log`、回调网关日志和 ngrok 状态；再核对云服务配额、授权及 ASR/TTS 配置。不要把日志中的 Key、Token 或完整回调地址发到公开渠道。
- Milvus 冷启动：健康端口和集合查询可能就绪于不同时间。启动会有限重试 503 并核对已有 89 条向量记录。若仍失败，先查看 Docker 容器和集合加载状态。
- 挂断清理失败：界面会退出本地通话并提示；运行关闭脚本核对云任务。

日志均在新工程 `.runtime`，配置在根 `.env`、`backend/.env` 和 `backend/voice_config.json`。这些文件已忽略，不能放入公开仓库。

## 4. 只看文本功能

```powershell
.\start.cmd
```

默认显式模拟生成和 sample 检索，不调用云模型。即使上一次手测使用 Milvus，模拟启动也会在原有商品语料上显式切到 sample，不要求旧向量服务在线。切换知识快照后，原快照下的 FAQ 不继续混用，这是版本隔离的预期行为。需要恢复真实语音时，先停止，再用语音启动脚本。

`start.ps1 -Live` 仅表示真实生成，保留当前知识版本；完整语音手测请使用 `start-voice.cmd`，由它明确选择 Milvus 并接好回调。

## 5. ngrok 配置位置

安装 ngrok 后，使用自己的账号在私有文件 `.runtime/ngrok-voice.yml` 中配置以下内容。

```yaml
version: '2'
authtoken: YOUR_PRIVATE_NGROK_TOKEN
web_addr: 127.0.0.1:4041
tunnels:
  fusion_voice_test:
    proto: http
    addr: 127.0.0.1:8011
```

启动脚本支持 `-NgrokExe`、`-NgrokConfig` 指定本机路径。预检会拒绝将运营 API 8010 或检查端口开放到公网，只允许通过 8011 上的已鉴权回调白名单。原项目配置不会被写回。
