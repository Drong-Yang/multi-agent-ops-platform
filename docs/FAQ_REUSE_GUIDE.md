# FAQ 与客服的反向联动：修复及使用说明

2026-11-21。针对用户测试发现的“发布资产后看不到客服复用”完成定位与优化。仅修改 `项目融合/电商运营Agent`，没有自动补写用户资产、修改原项目或进行真实 RTC 测试。

本页记录普通 FAQ 联动。售后 Wiki 的直接答复、补充资料及版本发布见 [售后 Wiki 与客服回答路径](SUPPORT_WIKI.md)。明确的售前规格题现在优先引用商品原文，混合咨询可继续验证普通 FAQ 的参考路径。

## 本次结论

原工程已经实现“审核 FAQ 作为后续问答的参考”，并非只能生成自媒体帖子。但原匹配条件及界面确有缺陷，不能归因于用户测试不到位。

只读检查发现，当前最近一份已发布 FAQ 的 `intent_tags` 为空。旧代码仅从可编辑的问题摘要提取六类主题标签，并要求本轮命中标签才查找资产，因此这份素材虽然发布了，却永远无法被选中。另有三处问题：通用政策没有 SKU 时被排除；追问的主题受前轮关键词干扰；撤回素材的旧答复仍可能通过模型历史上下文进入新一轮回答。

## 已做的优化

1. 根据**批准后的正文**推导匹配主题，兼容旧资产空标签；必要时采用保守的词法相关度。不额外请求一个模型来分类。
2. 有商品范围的素材必须匹配本轮商品；无商品范围的通用政策 FAQ 可以依据共同政策来源被选用，不再强行要求 SKU。
3. 优先判断当前问题主题，例如“那尺寸呢”不会仅因前轮问重量而选中只有重量的 FAQ。
4. 发布、批准正文哈希、来源任务、有效知识版本、账号归属及证据核验门禁继续生效。撤回、正文换版或知识换版后，新请求排除旧素材；不回收已经生成的答复或正在进行的请求。
5. 对本轮模型入参过滤失效 FAQ/旧知识对应的历史助手答复，保留用户原问题以支持多轮追问。数据库及页面历史不改写。
6. “内容资产”显示客服选用条件、商品范围、主题、验证问题及“去客服验证”入口。该按钮只新建会话并预填问题，不自动发送。
7. “客服试聊”每轮展示“FAQ 选用说明”：具体参考资产、摘录、匹配理由或未选用原因；可跳回原素材。历史记录仅保留当时信息，不伪造旧版未保存的诊断。

## 如何复测

如果当前中台还运行着修改前的后端，需要先结束通话再重启。按正在使用的真实语音启动方式：

```powershell
.\stop-voice.cmd
.\start-voice.cmd
```

随后刷新工作台，使用原账号：

1. 进入“内容资产”，找一份已经发布的 **FAQ 素材**，查看“客服选用条件”。旧资产无需删除重建或重新付费生成。
2. 点击“去客服验证”，确认页面切换到新文字会话，问题已预填，但未发送。
3. 点击“发送问题”，在回答下方查看“FAQ 选用说明”。选中后可看到具体资产摘录、匹配理由，并点击“查看这份素材”。
4. 撤回素材，再问同一问题。后续请求不再选用它，页面会给出当前未选用的说明。过去一轮的参考记录保留，这是历史记录，不代表撤回失效。
5. 换成不相关的商品或主题，不应为了演示强行命中该 FAQ。图文内容供内容发布，不能直接按 FAQ 发布给客服。

如果只运行模拟文本版，可以使用 `.\stop.cmd`、`.\start.cmd`，无需建立隧道；模拟版与真实 Milvus 知识快照不同，切换会使旧版本 FAQ 失效，不应混作同版本测试。

## 能否称作“补齐缺失知识”

**当前不能。** 基础商品/政策知识是事实依据；FAQ 是经过审批、绑定既有证据的表达资产。发布 FAQ 不会向基础 Milvus 集合写入新事实，也不会让缺少商品证据的问题凭生成稿获得事实答案。

真实流程是：

`同版商品/政策资料 → 客服咨询 → 确认摘要 → 内容任务 → 事实检查/人工审核 → FAQ 表达资产 → 后续咨询参考`

如要扩展为知识补录，应另加“知识缺口 → 人工提供可信来源及适用范围 → 校验新资料 → 构建新知识快照/向量索引 → 显式发布 → FAQ 重新核对”的流程。用户描述、模型回答或人工随手填写的答案均不能未经来源核验就自动晋升为商品事实。本轮没有将这种新能力伪装成已经实现。

当前每轮仍会检索并调用回答模型；FAQ 是回答参考，不是直接答案缓存。“选中”表示已加入本轮生成上下文，不保证模型逐字采用。没有本轮成本/效果对照数据，不能宣称已降低模型调用费用或实测提升准确率。

## 项目描述建议

可以描述为：

> 基于统一商品知识的电商运营 Agent，将客服咨询转为证据约束的内容任务，经事实检查与人工审核形成 FAQ 和图文资产；已发布 FAQ 可用于后续客服回答参考，并支持来源追溯、撤回与知识版本失效。

它同时支持客服表达沉淀和自媒体图文生产，无需把项目降格成只有“问答转帖子”，也不应夸大为已实现自动知识增长。
